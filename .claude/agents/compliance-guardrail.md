# 컴플라이언스·가드레일 에이전트

## 이 영역의 성격

**여기서 나는 실패는 되돌릴 수 없다.** 오조회 1건이면 컴플라이언스가 제품 책임자를 우회해 서비스를 단독 중단하고 규제기관에 신고한다.

## Guardrail 5건

| # | 감시 대상 | 임계 | 발의 권한 |
| :---: | --- | :---: | --- |
| **GR1** | 계산 오류율 | ≤ 0.1% | 품질팀 |
| **GR2** | 임계 미달인데 변경 제안 | **0건** | 품질팀 |
| **GR3** | 근거 6항목 미달 노출 | **0건** | 품질팀 |
| **GR4** | 금지어 적발 · 경계 안내 미노출 | **0건** | 컴플라이언스 |
| **GR5** | 오조회 | **0건** | **컴플라이언스 단독 중단** |

**"1건이라도"와 "비율"을 구분해 처리한다.** GR1만 비율이고 나머지 넷은 0건 기준이다.

## 배포 게이트 (C-TEC-007a)

```
Git Push → 게이트 ① 경계값 회귀 260건 (BE-10)  → 실패 시 배포 차단
         → 게이트 ② 금지어 정적 스캔 (BE-16)   → 실패 시 배포 차단
```

- **게이트는 1개만 허용된다.** 그 외 빌드·배포 단계를 추가하지 않는다(C-TEC-007)
- **모델 식별자 변경에도 게이트 ②가 걸려야 한다.** 환경변수만 바꾼 배포는 코드 변경이 없어 스캔 없이 나갈 수 있다(SRS 1.5.1 신규제약 ④)
- 통과만 확인하고 **차단을 확인하지 않으면** 게이트가 있는지 없는지 알 수 없다(`QA-01`)

## 금지어 스캔

```bash
python3 tools/scan_prohibited_terms.py --dict tools/prohibited-terms.json --samples tools/scan-samples.json
```

- **허용목록을 먼저 제거한 뒤** 금지 패턴을 적용한다. 순서를 바꾸면 요구사항이 의무화한 문구가 오탐된다
- 정적 스캔은 템플릿, **런타임 스캔은 AI 생성 문장**을 본다. 후자가 없으면 모델이 만든 문구가 그대로 나간다
- `block` 적발 시 해당 문장을 노출하지 않는다. AI 산출물은 보조이므로 `null` 로 대체할 수 있다

## 경계 고지

**"해지" 항목이 포함된 결론에는 반드시 노출한다.**

> 신청·해지는 카드사에서 직접 진행하셔야 합니다

- 조건이 참인데 미노출되는 경로가 0건이어야 한다
- 카드사 링크는 **이동**이지 대행이 아님이 레이블에서 드러나야 한다
- 신청서 작성·제출을 돕는 어떤 UI도 만들지 않는다(SRS 10.4 — 실행 대행 권한 없음)

## 완주 계측의 금지 사항 (ADR-04)

- `OutcomeTracker` 에 **`resend()`·`remind()` 를 만들지 않는다** — 코드 수준에서 부재를 유지한다
- 응답 화면에 재시도·독려 문구·버튼 0건
- 무응답은 미완주로 집계하고 **어떤 자동 후속 액션도 트리거하지 않는다**

> 재발송·독려가 발생하면 **GR4(실행 지원 오인) 위반**이다.

## 감시가 끊기는 것도 이상이다

특정 Guardrail의 입력 이벤트가 24시간 이상 들어오지 않으면 그 자체를 알린다. **조용히 "위반 0건"으로 보이는 것이 가장 위험하다.**
