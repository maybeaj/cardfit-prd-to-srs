# 계산 도메인 에이전트

**이 프로젝트에서 가장 위험한 코드를 다룬다.** 계산이 틀리면 사용자가 잘못된 금액을 보고, 게이팅이 틀리면 서비스가 중단된다(GR2).

## 시작 전 반드시 읽을 것

1. `docs/[계산 명세서] CardFit (한글).md` — **값의 유일한 정본**
2. `docs/[SRS 문서] CardFit (한글).md` §4.1.0 (RE-1~8이 왜 기획 결정이었나) · §4.1.1 (시퀀스)
3. `docs/[설계 문서] CardFit (한글).md` §3.1 · §6.2 · §6.3
4. `tools/generate_fixtures.py` 의 **참조 계산기** — 같은 명세를 옮긴 독립 구현

> **SRS 4.1.0을 값의 출처로 쓰지 않는다.** 그것은 "무엇을 정해야 했는가"의 기록이고, 값은 계산 명세에 있다.

## 파이프라인 순서 (RE-1)

```
S1 지출 정규화     시나리오 계수 적용 (적게 0.8 · 예상대로 1.0 · 많이 1.2) → 월 환산
S2 제외 거래 차감   실적 기준액과 혜택 기준액 양쪽에서 제거 (RE-2, exclusion_mode=BOTH)
S3 실적구간 판정    전월 실적 = 같은 시나리오의 월 지출 총액 (RE-4 정상 상태 가정), 경계는 ≥
S4 카테고리 혜택    floor(금액 × 혜택률) → 카테고리 한도 절사
S5 통합할인한도     카드별 월 상한 캡. 초과 시 혜택률 높은 카테고리부터 채운다
S6 조합 Gross 합산
```

**순서를 바꾸면 금액이 달라진다.** 한도를 제외 차감 전에 적용하면 다른 결과가 나온다.

## 게이팅 (RE-5 · D2)

```
전환비용 ⓐ 연회비 변동   = round((후보 연회비 합 − 현재 연회비 합) ÷ 12)   ← 음수 허용
전환비용 ⓑ 실적 재달성   = 5,000원 × 신규 진입 카드 수
전환비용 ⓒ 전환 실행     = round(10,000원 × 변경 항목 수 ÷ 12)

NetBenefit(C) = Gross(C) − 전환비용(C)
ΔNet(C)       = NetBenefit(C) − Gross(현재 조합)

RECOMMEND_CHANGE ⟺ ΔNet ≥ 3,000원/월  그리고  ΔNet ÷ Gross(현재) ≥ 0.10
```

- **두 조건을 모두** 만족해야 한다 — 하나만 통과한 후보를 제안하면 **GR2 위반**
- `Gross(현재) = 0` 이면 상대 판정 면제 (0으로 나누지 않는다)
- 유지 후보의 전환비용은 정의상 0원
- `KEEP_CURRENT` 는 `200` 정상 응답 — `error` 키를 두지 않는다

## 조합·배분 (RE-6·7·8)

- 보유카드 **사전 컷 8장** (최근 3개월 사용액 상위) → 부분집합 최대 256개
- 신규 후보 **3장**, 조합당 **최대 1장** 추가
- 제약 필터 — 최대 카드 수 · 연회비 상한 · 신규 발급 허용
- 최종 후보 **상한 20개**
- **정렬 5키 (전순서)** — ΔNet ↓ · 전환비용 ↑ · 카드 수 ↑ · 연회비 합 ↑ · `card_product_id` 사전순
- **RE-8 택일** — 카테고리 금액은 한 카드에만 배정. 배정 순서는 금액 ↓, 동점은 카테고리 코드 사전순
- 배분 합계 오차 ≤ 1원, 잔여는 최대 카테고리에 흡수

## 결정론 체크리스트

작업 후 아래를 코드에서 직접 확인한다.

- [ ] `Math.random()` 0건
- [ ] `new Date()` / `Date.now()` 0건 — 기준 시각은 주입받는다
- [ ] `Set`/`Map` 순회 순서에 의존하는 정렬 0건
- [ ] 부동소수 비교 0건 — 비율은 정수 교차곱으로
- [ ] 금액 타입이 전부 정수
- [ ] 정렬이 전순서인가 (동점에서 순서가 갈리지 않는가)

## 검증

```bash
python3 tools/generate_fixtures.py     # 참조 계산기와 대조
```

**페르소나 5인 × 시나리오 3개**의 결론이 `tools/fixtures/expected-results.json` 과 일치해야 한다. P2(+4,666원 · 6.5% → KEEP)가 게이팅 경계의 시험대다.

경계값 260건은 `tools/boundary-cases.json` 에 있고 `params_bound: true` 다(abs 3000 · rel 0.10 · delta 0.20).

## 하지 않는 것

- AI 호출 — `ExplanationModule` 은 결과를 인자로 받을 뿐이다 (ADR-02)
- 근거 조립 — `BE-11` 의 일이다
- 화면 표시 형식 — 서버가 준 정수를 화면이 그대로 쓴다
