# 프론트엔드 에이전트

## 시작 전 읽을 것

1. 대응 `DS-0N` 설계 태스크 — **시안 없이 화면을 만들지 않는다**
2. `docs/[SRS 문서] CardFit (한글).md` §6.3 (비즈니스 규칙 6·7) · §8.3 (정상 흐름)
3. `.claude/skills/vercel-react-best-practices/`

## 이 제품에서 가장 어려운 화면

**"그대로 두세요"를 실패나 오류로 보이지 않게 표현하는 것**(DS-03 · FE-03). 사용자는 무언가 바뀌기를 기대하고 들어왔고, 화면은 아무것도 바꾸지 말라고 답한다.

- `KEEP_CURRENT` 에 **실패색·경고 아이콘·재시도 버튼을 쓰지 않는다**
- 개선분이 0이 아닌데 유지인 경우(픽스처 P2, +4,666원 · 6.5%)를 문장으로 설명한다
- 유지 결론 화면에는 **조합안 선택 버튼이 없다** — 이 사용자는 북극성 분모에서 제외된다(ADR-05)

## 결과 화면 규칙

| 규칙 | 근거 |
| --- | :---: |
| 진입 시 **항상 "예상대로" 탭** | §6.3 규칙6 |
| 탭 전환 시 **네트워크 요청 0건** — 3건이 한 응답에 있다 | ADR-03 |
| 탭마다 **지출 가정 캡션** 필수 | §6.3 규칙7 |
| 금액은 서버가 준 정수를 그대로 — **화면에서 반올림·재계산하지 않는다** | REQ-NF-002 |
| 배분 합계가 입력 총액과 1원 넘게 어긋나면 **표시하지 않는다** | REQ-FUNC-005 |
| 전환비용이 **음수**(연회비 절감)여도 레이아웃이 깨지지 않아야 한다 | 픽스처 P3 |

## 예외 화면 7종

`CF-4001` · `CF-4002` · `CF-4030` · `CF-4100` · `CF-4221` · `CF-4222` · `CF-2001`

- **`CF-2001`만 오류가 아니다** — 결과와 **함께** 경고 배너로 표시하고 기준일을 붙인다
- `CF-4222`(부분 처리)에서는 **성공한 시나리오도 노출하지 않는다**
- `CF-4030` 화면은 타인 정보를 렌더링할 경로 자체를 갖지 않는다

## 계측 이벤트 7종

`input_done` · `result_viewed` · `evidence_expanded` · `scenario_tab_opened` · `onboarding_done`(`tag_selected` 포함) · `plan_selected` · `outcome_response`

**빠진 이벤트의 지표는 영구히 측정 불가가 된다.** 화면을 만들 때 함께 심는다.

## 입력 화면 규칙

- **직접 입력 강제 필드 0개** — 초기값이 채워진 상태로 시작한다(REQ-FUNC-007)
- **이벤트·태그 선택 단계를 만들지 않는다** — 없음으로 충족되는 요구사항이다(REQ-FUNC-008)
- 자유 카테고리 문자열을 거부하지 않는다
- 지출 **감소 방향**을 오류 없이 처리한다

## 전 화면 공통

**"시연용 가공 데이터" 배지를 노출한다.** 실제 카드사명을 쓰므로 선택 사항이 아니다(FXT 2.1절).

## 개발 방식

Mock(`MK-01`·`MK-02`) 기반으로 **백엔드 완성을 기다리지 않고** 개발한다. Mock 숫자는 `tools/fixtures/expected-results.json` 에서 파생된 값이라 실제 구현과 갈라지지 않는다.
