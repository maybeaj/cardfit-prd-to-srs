# 에러 진단

대상: **$ARGUMENTS**

## Step 0. 불변식 위반부터 의심한다

증상이 아래에 해당하면 **일반 디버깅보다 먼저** 그 원인을 확인한다.

| 증상 | 첫 번째 용의자 |
| --- | --- |
| 같은 입력에 다른 금액 | **I1** — AI가 계산 경로에 개입했는가 (ADR-02) · **I3** — 비결정론 |
| 배분 합계 오차 | **I2** — 부동소수가 계산 경로에 있는가 |
| 임계 미달인데 변경 제안 | **I4** — 두 조건 중 하나만 검사했는가 |
| 근거가 5개인데 응답이 나감 | **I5** — 게이트가 AI 뒤에 있는가 |
| 타인 데이터 노출 | **I6** — 즉시 중단. 컴플라이언스 통보 대상 |
| 마이데이터 호출 2회 이상 | `collectOnce` 가 시나리오 반복문 **안**에 있는가 |

## Step 1. 현상 정의
관찰된 증상·재현 조건·에러 원문·스택트레이스를 그대로 옮긴다.

## Step 2. 맥락 탐색
관련 파일과 호출 경로를 지도화한다. 계산 관련이면 **S1~S6 중 어느 단계인지** 특정한다.

## Step 3. 근본 원인 특정
가설이 여러 개면 각각의 근거와 반증을 나열한다. **명세와 코드가 다르면 어느 쪽이 틀렸는지 판정한다** — 명세가 틀렸으면 코드로 우회하지 않고 명세를 고친다.

## Step 4. 쉬운 말로 요약
"무엇이 왜 잘못되었는가"를 한 문단으로. 전문용어를 최소화한다.

## Step 5. 수정 포인트
파일:라인과 이유를 목록화한다.

## Step 6. 수정
원저자 의도를 보존하고 **한 번에 한 가지**만 고친다. 리팩터링을 섞지 않는다.

## Step 7. 재발 방지
- 이 에러를 잡는 테스트가 STD에 있는가? 없으면 어느 TC에 추가할지 제안한다
- 경계값 260건에 해당 케이스가 있는가?
- 후속 개선은 별도 작업으로 제시하고 지금 반영하지 않는다
