# 계산·게이팅 규칙

**값의 정본은 `docs/tech-design-docs/[CALC]cardfit-calc-spec.md` 다.** SRS 4.1.0은 "무엇을 정해야 했는가"의 기록이고, 값은 계산 명세에 있다.

## 결정론 — 금지 목록

계산·조합·배분·근거 조립 경로에서:

- `Math.random()`
- `new Date()` / `Date.now()` — **기준 시각은 주입받는다**
- `Set`·`Map` 순회 순서, 객체 키 순서에 의존하는 정렬
- 부동소수 비교 — 비율 판정은 **정수 교차곱**으로

**정렬은 전순서여야 한다.** 조합 후보 5키: `ΔNet ↓` · 전환비용 ↑ · 카드 수 ↑ · 연회비 합 ↑ · `card_product_id` 사전순.

> 동일 입력 10회 반복의 응답 해시가 모두 같아야 한다(REQ-NF-002 · 배포 게이트 ①). 불일치가 나오면 **AI가 계산에 개입했는지(ADR-02)부터 확인한다.**

## 파이프라인 순서 — 바꾸면 금액이 달라진다

```
S1 지출 정규화 (시나리오 계수 0.8 / 1.0 / 1.2 → 월 환산)
S2 제외 거래 차감 (실적·혜택 양쪽)
S3 실적구간 판정 (전월 실적 = 같은 시나리오 월 지출, 경계 ≥)
S4 카테고리 혜택 (floor → 카테고리 한도)
S5 통합할인한도 (혜택률 높은 카테고리부터)
S6 조합 Gross 합산
```

## 게이팅 — 두 조건을 모두

```
NetBenefit(C) = Gross(C) − 전환비용(C)
ΔNet(C)       = NetBenefit(C) − Gross(현재 조합)

RECOMMEND_CHANGE ⟺ ΔNet ≥ 3,000원/월  그리고  ΔNet ÷ Gross(현재) ≥ 0.10
```

| 항목 | 값 |
| --- | --- |
| 전환비용 ⓐ | `round((후보 연회비 합 − 현재 연회비 합) ÷ 12)` — **음수 허용** |
| 전환비용 ⓑ | `5,000원 × 신규 진입 카드 수` |
| 전환비용 ⓒ | `round(10,000원 × 변경 항목 수 ÷ 12)` |
| `Gross(현재) = 0` | 상대 판정 **면제** (0으로 나누지 않는다) |
| 유지 후보 | 전환비용 정의상 0원 |

**하나만 통과한 후보를 제안하면 GR2 위반이고 서비스가 중단된다.** 픽스처 P2(+4,666원 · 6.5%)가 이 경계의 시험대다.

`KEEP_CURRENT` 는 `200` 정상 응답이며 `error` 키를 두지 않는다.

## 근거 게이트

- 공개 6항목 — 실적구간 · 통합할인한도 · 연회비 · 제외조건 · 기준일 · 미반영 항목
- 미달 시 `CF-4221`. **부분 근거를 응답에 싣지 않는다**
- `unreflectedItems` 는 비어도 **키를 생략하지 않는다**
- 미반영 항목 표준 목록 6건은 계산 명세 3.5절

## 검증

```bash
python3 tools/generate_fixtures.py     # 참조 계산기와 대조
```

페르소나 5인 × 시나리오 3개가 `tools/fixtures/expected-results.json` 과 일치해야 한다. 경계값 260건은 `tools/boundary-cases.json`(`params_bound: true`).

**참조 계산기는 제품 구현이 아니다.** 두 구현이 같은 명세에서 독립적으로 나와야 대조가 의미를 갖는다. 다만 **같은 방식으로 잘못 읽으면 나란히 틀린다** — 그 위험은 경계값 260건이 다른 각도에서 덮는다.
