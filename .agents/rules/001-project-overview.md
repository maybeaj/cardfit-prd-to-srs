# Project Overview

## Vision

카드 조합 재설계를 **판단 가능한 결정**으로 바꾼다. 사용자는 자기 카드가 지금 지출에 맞는지 알 수 없고, 비교 서비스는 언제나 무언가를 바꾸라고 말한다. CardFit은 **바꿀 만하지 않으면 바꾸지 말라고 답한다.**

## Core Features

| 기능 | 요구사항 |
| --- | :---: |
| 미래지출 입력 (자유 카테고리 · 증감 양방향) | REQ-FUNC-001 · 008 |
| 마이데이터 연동 · 제약조건 수집 | REQ-FUNC-002 |
| **순혜택 시나리오 3개 사전 계산** (적게·예상대로·많이) | REQ-FUNC-003 |
| **조합 최적화 + Net Benefit 게이팅** | REQ-FUNC-004 |
| 결제수단 배분 (합계 오차 ≤ 1원) | REQ-FUNC-005 |
| **계산 근거 6항목 공개** | REQ-FUNC-006 |
| 과거 패턴 기반 초기값 제안 | REQ-FUNC-007 |
| 스코프 경계 고지 · 금지어 검수 | REQ-FUNC-009 |
| 실행 완주율 계측 (측정 전용) | REQ-FUNC-010 |

## 성공 기준

| 지표 | 목표 |
| --- | :---: |
| **북극성 — 조합안 선택률** | ≥ 40% |
| 온보딩 완료율 | ≥ 60% |
| 결론 도달 시간 | p95 ≤ 5분 |
| 근거 열람률 | ≥ 50% |
| 범위 인지율 | ≥ 90% |

**북극성에는 분모 제외가 있다** — "예상대로" 결론이 "유지"인 사용자는 분모에서 빠진다(ADR-05). 이것이 없으면 게이팅을 정직하게 지킬수록 지표가 떨어진다.

## 범위 밖

- **실행 대행** — 신청·해지·자동이체 변경을 대신하지 않는다
- 정기 재진단 · 대량 보유 카드 최적화 (SRS 7장 향후 개선)
- 수익모델 확정 (D3 — v1 시연 범위 밖)

## 철학

1. **정직이 기능이다.** 계산에 넣지 못한 것은 미반영 항목으로 드러낸다
2. **결정론이 신뢰를 만든다.** 같은 입력은 언제나 같은 금액을 낸다
3. **막는 장치를 먼저 세운다.** 의존성 린트·배포 게이트는 코드가 쌓이기 전에 만든다
