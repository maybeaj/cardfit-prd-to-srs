### 0.1 근거와 범위

본 태스크 리스트는 **SRS 요구사항 27건 · 기술 제약 8건 · 데이터 모델 15테이블 · API 7행**을 실행 가능한 단위로 분해한 것이다.

- SRS에 **명시되지 않은 기능은 추가하지 않았다.** 모든 태스크는 `관련 SRS 섹션` 열로 원문을 지목한다.
- 향후 개선 대상(SRS 7장)은 **태스크로 만들지 않았다.**
- 조건부 범위(Could — REQ-FUNC-011·012)는 `BE-04`·`BE-08`·`FE-02`·`FE-03`에 포함돼 있다.
- **픽스처 모드가 기본이다.** 외부 연동은 어댑터 뒤에 있고, 계산·게이팅·인증·감사는 실제 코드가 그대로 돈다(FXT 1장).

## 6. 이 리스트의 한계

1. **`BE-01`(인증·세션)은 방식이 미명시다.** SRS 4.2 REQ-NF-004가 *"모든 API에 인증 요구"* 만 규정하고 인증 수단·회원가입 플로우를 정하지 않았다. **이번 개정에서 풀리지 않은 유일한 명세 공백이다.**
2. **픽스처의 혜택 규칙은 실제 상품과 다르다.** 검증되는 것은 **계산 로직**이지 혜택 정보가 아니다. 실제 카드사명을 쓰므로 화면 배지와 문서 면책이 함께 가야 한다(FXT 2.1·9장).
3. **`QA-04`는 명세 오독을 잡지 못한다.** 참조 계산기와 제품 구현이 **같은 방식으로** 명세를 잘못 읽으면 두 값이 나란히 틀린다. 이 위험은 경계값 260건(BE-10)이 다른 각도에서 덮는다.
4. **복잡도는 그룹 안 최고 난이도다.** 작업량 합계가 아니므로 일정 산정에는 `작업 수` 열을 함께 본다.
5. **`FE-03`(8건)과 `TS-01`(12건)은 한 사람이 맡기 어렵다.** 분담이 필요하면 이 둘만 다시 쪼갠다.
6. **`FE-08`은 SRS가 요구하지만 세부 화면 구성이 미정이다.** 지표 4층과 Guardrail 5건을 한 화면에 어떻게 배치할지는 `DS-05`가 정한다.
