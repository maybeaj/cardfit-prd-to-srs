## 0. 이 문서를 읽는 법

### 0.1 근거와 범위

본 태스크 리스트는 **SRS 요구사항 27건 · 기술 제약 8건 · 데이터 모델 15테이블 · API 7행**을 실행 가능한 단위로 분해한 것이다.

- SRS에 **명시되지 않은 기능은 추가하지 않았다.** 모든 태스크는 `관련 SRS 섹션` 열로 원문을 지목한다.
- 향후 개선 대상(SRS 7장)은 **태스크로 만들지 않았다.**
- 조건부 범위(Could — REQ-FUNC-011·012)는 `BE-04`·`BE-08`·`FE-02`·`FE-03`에 포함돼 있다.

### 0.2 관점 분리

## 6. 이 리스트의 한계

1. **`BE-01`(인증·세션)은 방식이 미명시다.** SRS 4.2 REQ-NF-004가 *"모든 API에 인증 요구"* 만 규정하고 인증 수단·회원가입 플로우를 정하지 않았다.
2. **`IN-06`은 도구가 미선정이다.** SRS 1.5.2 갈래④가 *"스택에 수단이 없다"* 고 식별한 항목(APM · 알림 · 발송 · 분석)이며, D14 결정이 선행된다.
3. **복잡도는 그룹 안 최고 난이도다.** 작업량 합계가 아니므로 일정 산정에는 `작업 수` 열을 함께 본다.
4. **`FE-03`(8건)과 `TS-01`(12건)은 한 사람이 맡기 어렵다.** 분담이 필요하면 이 둘만 다시 쪼갠다.
5. **`FE-08`은 SRS가 요구하지만 세부 화면 구성이 미정이다.** 지표 4층과 Guardrail 5건을 한 화면에 어떻게 배치할지는 `DS-05`가 정한다.
