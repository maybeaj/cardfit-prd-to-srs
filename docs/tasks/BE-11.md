## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 6항목이 계산 단계에서 채워진다**
- Given: 완료된 계산 1건이 주어지고
- When: 근거를 조립하면
- Then: 6항목이 모두 채워지고 각 값이 해당 계산 단계의 산출물과 일치한다(CALC §8장).

**Scenario 2: 미반영 항목이 항상 노출된다**
- Given: 정상 계산이 주어지고
- When: 근거를 조립하면
- Then: 표준 목록 6건이 `unreflectedItems` 에 포함된다. 계산이 구조적으로 담지 못하는 것을 숨기지 않는다(§6.3 규칙3).

**Scenario 3 (실패 흐름): 근거 조립이 계산을 재실행하지 않는다**
- Given: 근거 조회 요청이 주어지고
- When: 실행 경로를 추적하면
- Then: 계산 엔진 호출이 0건이다. 재계산하면 결정론(REQ-NF-002)과 응답 시간(p95 ≤ 1s)이 함께 위험해진다.

**Scenario 4 (실패 흐름): 빈 미반영 목록에서도 키가 남는다**
- Given: 미반영 항목이 하나도 없는 상황이 주어지고
- When: 응답을 직렬화하면
- Then: `unreflectedItems: []` 로 키가 존재한다. 생략하면 "표기 누락"과 "해당 없음"을 구분할 수 없다.
