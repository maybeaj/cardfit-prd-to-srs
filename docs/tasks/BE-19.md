## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 계산 응답이 계약과 일치한다**
- Given: 정상 계산 요청이 주어지고
- When: `POST /calculate` 를 호출하면
- Then: 응답이 CT-01 스키마 검증을 통과하고 시나리오 3건·`defaultScenario: AS_EXPECTED` 를 포함한다.

**Scenario 2 (실패 흐름): 예외가 CF 코드로 나간다**
- Given: 미래 입력 0건·동의 만료·근거 미달 요청이 각각 주어지고
- When: 해당 엔드포인트를 호출하면
- Then: `CF-4001`·`CF-4002`·`CF-4221` 이 각각 반환되고 `requirement` 가 채워진다(§6.1.2).

**Scenario 3: 레이턴시가 계측된다**
- Given: 엔드포인트를 여러 번 호출한 뒤
- When: `latency_samples` 로 p50·p95·p99를 산출하면
- Then: 계산 p95 ≤ 5s · 근거 p95 ≤ 1s를 확인할 수 있다(REQ-NF-001).

**Scenario 4 (실패 흐름): 실행 개입 엔드포인트가 없다**
- Given: 노출된 라우트 목록이 주어지고
- When: 실행 대행·재발송·독려에 해당하는 엔드포인트를 세면
- Then: 0개다. 측정 전용 구조를 프로토콜에서 지킨다(ADR-04).
