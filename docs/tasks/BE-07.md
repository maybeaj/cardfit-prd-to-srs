## ✅ Task Breakdown (실행 계획)
- [ ] **전환비용 ⓐ 연회비 변동** — `round((후보 연회비 합 − 현재 연회비 합) ÷ 12)`. **음수를 허용한다**
- [ ] **전환비용 ⓑ 실적 재달성 부담** — `5,000원 × 신규 진입 카드 수`
- [ ] **전환비용 ⓒ 전환 실행 부담** — `round(10,000원 × 변경 항목 수 ÷ 12)`. 변경 항목 = 해지 + 신규 발급 + 주력 카테고리 재배정
- [ ] "신규 진입 카드"·"변경 항목"·"현재 조합"의 정의를 코드 주석으로 고정(CALC §3.1 용어 표)
- [ ] **`NetBenefit(C) = Gross(C) − 전환비용(C)`** 구현
- [ ] **`ΔNet(C) = NetBenefit(C) − Gross(현재 조합)`** 구현 — SRS의 "Net Benefit ≥ 임계값"은 이 개선분 기준이다(CALC §3.2)
- [ ] **절대 판정** — `ΔNet ≥ 3,000원/월`. 경계는 이상(≥)
- [ ] **상대 판정** — `ΔNet ÷ Gross(현재) ≥ 0.10`. **`Gross(현재) = 0` 이면 상대 판정 면제**
- [ ] **두 조건을 모두 만족할 때만 `RECOMMEND_CHANGE`** — 하나만 통과한 후보를 제안하면 GR2 위반
- [ ] 유지 후보의 전환비용은 정의상 0원으로 처리
- [ ] Guardrail 감시 훅 — 판정 결과를 `GuardrailMonitor`(`BE-18`)가 읽을 수 있게 기록
- [ ] 경계 테스트 — 임계값 ±1원, 상대 기준 9.9%/10.0%/10.1%

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 두 조건을 모두 넘으면 변경을 권고한다**
- Given: `Gross(현재) = 32,000원` 이고 후보의 `ΔNet = 5,167원`(16.1%)인 상태에서
- When: 게이팅을 판정하면
- Then: `RECOMMEND_CHANGE` 와 차액이 반환된다(CALC §3.4 사례 나).

**Scenario 2 (실패 흐름): 상대 기준만 미달해도 유지다**
- Given: `Gross(현재) = 32,000원` 이고 후보의 `ΔNet = 3,167원`(9.9%)인 상태에서
- When: 게이팅을 판정하면
- Then: `KEEP_CURRENT` 다. 절대 기준은 넘었지만 상대 10%에 못 미친다 — **이 케이스를 변경으로 제안하면 GR2 위반이다**(CALC §3.4 사례 가 · 픽스처 P2).

**Scenario 3 (실패 흐름): 현재 혜택이 0이면 상대 판정을 하지 않는다**
- Given: 보유 카드가 없어 `Gross(현재) = 0` 인 상태에서
- When: 게이팅을 판정하면
- Then: 절대 판정만 적용되고 0으로 나누는 경로가 실행되지 않는다(CALC §3.3).

**Scenario 4 (실패 흐름): 임계 미달 전건이 유지로 반환된다**
- Given: 임계 미달 케이스 전건이 주어지고
- When: 판정 결과를 임계값과 대조하면
- Then: "유지" 반환률 100% · 임계 미달인데 변경 제안 0건이다(AC-05 · TC-FUNC-004).

## ⚙️ Technical & Non-Functional Constraints
- 규제·품질: **GR2** — 임계 미달인데 변경을 제안한 건수 1건이면 즉시 서비스 중단이다
- 정확성: **REQ-NF-002** 결정론. 판정에 부동소수 비교를 쓰지 않는다(비율 비교는 정수 교차곱으로)
- 제품: **ADR-01** "유지"는 실패가 아니라 정상 결과다. `200` 으로 반환하며 `error` 키를 두지 않는다
- 값의 정본: **CALC §1장** — 절대 월 3,000원 · 상대 10% · 계수 5,000/10,000원. 변경 시 `rule_spec_version` 을 올리고 경계값 260건을 재바인딩한다
