## ✅ Task Breakdown (실행 계획)
- [ ] 온보딩 플로우 설계 — 마이데이터 동의 → 수집 확인 → 초기값 제안 확인 → 제약조건 입력
- [ ] **동의 화면 설계** — 수집 항목과 범위를 최소로 보이게. 동의 범위 최소화는 REQ-NF-004 요건이다
- [ ] **초기값 제안 화면** — 제안값이 이미 채워진 상태로 시작하고, 수정하지 않아도 다음으로 갈 수 있어야 한다
- [ ] **직접 입력 강제 필드 0개 검증표** — 각 단계의 필수 입력을 세어 0임을 명시한다(REQ-FUNC-007 판정 SLO)
- [ ] **이벤트·태그 선택 단계를 두지 않는다** — 이벤트 비종속(REQ-FUNC-008)은 "단계를 만들지 않음"으로 충족된다
- [ ] 자유 카테고리 입력 UI — 목록에 없는 문자열을 거부하지 않는 입력 방식
- [ ] **증감 양방향 입력** — 지출 감소(음수 방향)를 자연스럽게 표현하는 컨트롤
- [ ] **범위 입력(최소~평균)** — 조건부 범위(REQ-FUNC-012)로, 단일값과 전환 가능한 형태
- [ ] 제약조건 입력 — 최대 카드 수·연회비 상한·신규 발급 허용 여부
- [ ] 이탈 지점 가설과 계측 포인트 표기 — `onboarding_done`(`tag_selected` 포함) · `input_done` 이벤트가 붙을 자리

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 수정 없이 온보딩을 끝낼 수 있다**
- Given: 초기값 제안 화면이 설계된 상태에서
- When: 사용자가 아무 값도 고치지 않고 진행하면
- Then: 다음 단계로 넘어가고 결론까지 도달할 수 있다. 직접 입력 강제 필드가 0개다(REQ-FUNC-007).

**Scenario 2: 이벤트를 고르지 않고 통과한다**
- Given: 온보딩 전 구간 설계가 주어지고
- When: 이벤트·태그 선택을 요구하는 단계를 세면
- Then: 0개다. `tag_selected=false` 로도 완주가 성립한다(REQ-FUNC-008 · TC-FUNC-008).

**Scenario 3 (실패 흐름): 자유 카테고리가 거부되지 않는다**
- Given: 카테고리 입력 UI가 주어지고
- When: 목록에 없는 문자열을 입력하면
- Then: 거부되지 않고 저장 경로로 이어진다. 거부하면 REQ-FUNC-001의 자유 입력 요건이 깨진다.

**Scenario 4 (실패 흐름): 감소 방향 입력이 막히지 않는다**
- Given: 금액 입력 컨트롤이 주어지고
- When: 지출이 줄어드는 방향을 입력하면
- Then: 오류 없이 처리된다. 감소 방향 처리 실패는 0건이어야 한다(AC-07).
