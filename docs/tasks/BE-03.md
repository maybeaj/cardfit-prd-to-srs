## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 시나리오 3건에도 호출은 1회다**
- Given: 미래지출과 보유카드가 준비된 사용자가 주어지고
- When: 계산을 1회 요청하면
- Then: 마이데이터 호출 수가 1이다. 3회면 REQ-NF-005 위반이다(TC-NF-005).

**Scenario 2: 장애 시 경고와 함께 계산이 계속된다**
- Given: 프로바이더에 타임아웃을 주입하고 최근 스냅샷이 있는 사용자가 주어지고
- When: 계산을 요청하면
- Then: `CF-2001` 경고와 기준일이 붙은 정상 결과가 반환된다. 무단 중단 0건(REQ-EXC-003).

**Scenario 3 (실패 흐름): 스냅샷이 없으면 중단한다**
- Given: 스냅샷이 없는 신규 사용자에게 장애를 주입하고
- When: 계산을 요청하면
- Then: 필수 데이터 누락으로 처리되고 결과가 생성되지 않는다.

**Scenario 4 (실패 흐름): 예산을 넘는 호출이 차단된다**
- Given: 같은 결론에 대해 이미 1회 수집이 기록된 상태에서
- When: 추가 수집을 시도하면
- Then: 호출이 발생하지 않고 예산 초과가 기록된다(REQ-NF-005).

## ⚙️ Technical & Non-Functional Constraints
- 비용: **REQ-NF-005** 결론 1건당 호출 ≤ 1회 · 시나리오 확장으로 인한 추가 호출 0건. 마이데이터는 호출당 과금된다
- 안정성: **REQ-EXC-003** 장애 시 경고 표시 후 계속. 필수 데이터 누락 시에만 중단
- 기술 제약: 서버리스라 **카운터를 DB에 둔다**(§1.5.2 갈래③)
- 아키텍처: **SDD §2.4 규칙 3** — 외부 호출은 이 컴포넌트만 한다
