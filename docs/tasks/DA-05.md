## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 24종이 손실 없이 적재된다**
- Given: 빈 DB와 픽스처 파일이 주어지고
- When: 시드 로더를 실행하면
- Then: `card_products` 24행과 각 상품의 `benefit_rules` 가 적재되고, 실적구간·한도·제외항목이 원본과 일치한다.

**Scenario 2: 두 번 실행해도 중복되지 않는다**
- Given: 시드가 이미 적재된 상태에서
- When: 로더를 한 번 더 실행하면
- Then: 행 수가 늘지 않는다. 중복이 생기면 계산이 같은 상품을 두 번 후보로 잡는다.

**Scenario 3 (실패 흐름): 구조가 어긋나면 적재를 중단한다**
- Given: 필수 필드가 빠진 픽스처 파일이 주어지고
- When: 로더를 실행하면
- Then: 부분 적재 없이 실패한다. 절반만 들어간 카탈로그는 계산 결과를 조용히 틀리게 만든다.

**Scenario 4: 최신성 판정이 즉시 동작한다**
- Given: 시드가 적재된 상태에서
- When: `verified_at` 을 31일 전으로 바꾸고 최신성 점검을 돌리면
- Then: 해당 카드가 계산 대상에서 제외된다(REQ-NF-007 · `BE-13` 연계).

## ⚙️ Technical & Non-Functional Constraints
- 기술 제약: **C-TEC-003** Prisma 시드 스크립트로 구현한다
- 정확성: 금액·한도는 원 단위 정수로 적재한다. 변환 과정에서 실수형을 거치지 않는다
