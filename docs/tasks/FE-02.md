- [ ] 미래지출 입력 폼 — 카테고리·금액·시점·확실도
- [ ] **자유 카테고리 입력** — 목록에 없는 문자열을 거부하지 않는다. 제안 목록은 보조일 뿐 제한이 아니다

- [ ] **이벤트·태그 선택 단계를 만들지 않는다** — 없음으로 충족되는 요구사항이다(REQ-FUNC-008)
- [ ] 제약조건 입력 — 최대 카드 수·연회비 상한·신규 발급 허용 여부
- [ ] **입력 0건 상태의 계산 요청 처리** — `CF-4001` 수신 시 입력 요구 화면. 결과 화면으로 넘어가지 않는다

- [ ] 컴포넌트 테스트 — 자유 문자열, 감소 방향, 범위 입력, 0건 거부

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 자유 카테고리가 저장된다**
- Given: 입력 화면이 열린 상태에서
- When: 목록에 없는 카테고리 문자열과 금액·시점·확실도를 입력해 저장하면
- Then: 거부 없이 저장된다. 자유 카테고리 거부 0건이 판정 기준이다(TC-FUNC-001).

**Scenario 2: 지출 감소 방향이 처리된다**
- Given: 입력 화면이 열린 상태에서
- When: 지출이 줄어드는 방향으로 금액을 입력해 저장하면
- Then: 오류 없이 저장된다. 감소 방향 처리 실패 0건(AC-07).

**Scenario 3 (실패 흐름): 이벤트 선택 단계가 존재하지 않는다**
- Given: 입력 화면 전 구간이 주어지고
- When: 이벤트·태그 선택을 요구하는 단계를 세면
- Then: 0개다(REQ-FUNC-008).

**Scenario 4 (실패 흐름): 미래 입력 0건이면 결과로 가지 않는다**
- Given: 미래지출이 0건인 상태에서
- When: 계산을 요청하면
- Then: `CF-4001` 을 받아 입력 요구 화면이 표시되고, 어떤 결과도 노출되지 않는다(REQ-EXC-001 · §6.3 규칙1).

## ⚙️ Technical & Non-Functional Constraints
- 사용성: **REQ-NF-008** 직접 입력 강제 0개. 초기값이 채워진 상태에서 시작한다(FE-01 연계)
- 정확성: 금액은 **원 단위 정수**로 전송한다. 화면에서 소수점을 만들지 않는다(REQ-NF-002 · REQ-FUNC-005)
