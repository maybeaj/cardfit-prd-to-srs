## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 시나리오가 3건을 넘지 않는다**
- Given: 한 계산에 `AS_EXPECTED` 시나리오가 이미 있는 상태에서
- When: 같은 타입의 행을 하나 더 넣으려 하면
- Then: `UNIQUE` 제약으로 DB가 거부한다(REQ-FUNC-003).

**Scenario 2: 조합안은 만료 시점 없이 존재할 수 없다**
- Given: `plan_candidates` 가 생성된 상태에서
- When: `expires_at` 없이 행을 삽입하면
- Then: `NOT NULL` 제약으로 거부된다. 만료 없는 조합안은 REQ-EXC-006을 위반한다.

**Scenario 3 (실패 흐름): 게이팅 결과가 임의 값을 갖지 못한다**
- Given: `plan_candidates` 가 생성된 상태에서
- When: `gating_result` 에 두 값 외의 문자열을 넣으면
- Then: `CHECK` 제약으로 거부된다(SDD §4.2).

**Scenario 4: 입력 스냅샷으로 재현이 가능하다**
- Given: 완료된 계산 1건이 주어지고
- When: `calculation_input_plans` 와 `calculation_applied_rules` 를 조회하면
- Then: 어떤 미래계획과 어떤 `rule_version` 이 쓰였는지 전건 확인된다(REQ-NF-006).

## ⚙️ Technical & Non-Functional Constraints
- 기술 제약: **C-TEC-003** Prisma 정본. 금액 컬럼은 `BigInt` 원 단위
- 정확성: 배분 합계 오차 ≤ 1원은 **DB가 지켜주지 않는다.** 애플리케이션(`AllocationService`)과 일간 배치가 검증한다(SDD §4.2)
- 감사: **REQ-NF-006** 입력 스냅샷 전건 보존. 파생 테이블 3종이 그 수단이다(§6.4.3)
- 상태: **§6.5 상태 전이 규칙** — `PARTIAL` 은 결과로 취급하지 않는다
