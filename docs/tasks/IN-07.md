## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 30일 대기가 큐 없이 성립한다**
- Given: 데모 클럭 `outcome_seeds` 2건이 적재된 상태에서
- When: 완주 계측 배치를 실행하면
- Then: 두 건이 발송 대상으로 조회되고 `outbox` 에 적재된다(REQ-FUNC-010).

**Scenario 2 (실패 흐름): 배치를 두 번 돌려도 재발송하지 않는다**
- Given: 발송이 이미 기록된 상태에서
- When: 배치를 한 번 더 실행하면
- Then: 재발송이 0건이다. `outcome_logs.status` 전이가 이를 막는다(ADR-04 · GR4).

**Scenario 3: 실행시간 실측이 기록된다**
- Given: 카드 3·5·10장 케이스가 준비된 상태에서
- When: 3개 시나리오 계산을 수행하며 소요를 측정하면
- Then: 각 케이스의 소요와 서버리스 상한 대비 여유가 문서로 남는다(D15).

**Scenario 4 (실패 흐름): 30일 초과 카드가 계산에서 빠진다**
- Given: `verified_at` 이 31일 전인 카드가 있는 상태에서
- When: 최신성 점검 배치를 실행하면
- Then: 해당 카드가 계산 대상에서 제외되고 경고가 적재된다(REQ-NF-007).
