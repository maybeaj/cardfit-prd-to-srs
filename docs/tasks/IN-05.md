## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 환경변수만 바꿔 모델이 교체된다**
- Given: 기본 모델로 동작하는 앱이 주어지고
- When: 모델 식별자 환경변수만 다른 값으로 바꿔 배포하면
- Then: 호출부 코드 변경 없이 새 모델로 호출된다(C-TEC-006).

**Scenario 2 (실패 흐름): AI가 실패해도 근거는 나간다**
- Given: AI 호출이 타임아웃되는 상태에서
- When: 근거 조회를 수행하면
- Then: `termsSummary` · `rationale` 이 `null` 이고 근거 6항목은 그대로 반환된다. AI는 보조 기능이므로 실패가 응답을 막지 않는다(§6.1.3).

**Scenario 3 (실패 흐름): 호출 예산을 넘으면 호출하지 않는다**
- Given: 같은 근거에 대해 AI 호출이 이미 1회 수행된 상태에서
- When: 추가 호출을 시도하면
- Then: 호출이 발생하지 않고 예산 초과가 기록된다(REQ-NF-005 · §1.5.1 신규 제약 ③).

**Scenario 4: 픽스처 모드에서는 외부 호출이 0건이다**
- Given: `CARDFIT_DATA_MODE=fixture` 로 기동한 상태에서
- When: AI 설명이 필요한 경로를 전부 통과시키면
- Then: 외부 AI 호출이 0건이고 캐시 경로만 사용된다(FXT §1장).

## ⚙️ Technical & Non-Functional Constraints
- 기술 제약: **C-TEC-005** 자체 서버 없이 Vercel AI SDK · **C-TEC-006** Gemini 기본 + 환경변수 교체
- 비용: **AI 호출은 외부 과금이다.** REQ-NF-005는 마이데이터 과금만 다루므로, 이 태스크가 AI 토큰·과금액을 모니터링 항목에 추가한다(§1.5.1 신규 제약 ③)
- 규제: **DEC-3a**(약관 요약)는 공개 문서라 전송 가능. **DEC-3b**(근거 설명)는 픽스처 모드에서만 해소된 상태이며, 실사용자 데이터 전환 시 재검토 대상이다(SRS §10.3)
- 아키텍처: **ADR-02** — 이 래퍼는 계산 모듈을 import 하지 않는다. IN-04 린트의 검사 대상이다
