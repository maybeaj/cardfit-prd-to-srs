## ✅ Task Breakdown (실행 계획)
- [ ] **"유지" 결론 화면 설계** — 결론 문장·색·아이콘·후속 행동. 실패색·경고 아이콘을 쓰지 않는다
- [ ] **"유지" 결론의 근거 요약 표현** — *"바꾸면 월 4,666원 늘지만 지금 대비 6.5%라 기준에 못 미칩니다"* 를 화면 문장으로. 개선분이 0이 아닌데 유지라고 말하는 가장 어려운 경우(픽스처 P2)
- [ ] **"변경" 결론 화면 설계** — 조합안·차액(원 단위)·전환비용 3항목 내역
- [ ] **전환비용이 음수인 경우** 표현 — 연회비 절감으로 부담이 이득이 되는 사례(픽스처 P3)
- [ ] 탭 3개 구조 — 기본은 **항상 "예상대로"**(§6.3 규칙6). 적게·많이는 보조 탐색이며 기본 결론을 대체하지 않는 위계로
- [ ] **탭별 가정 캡션** — "예상보다 20% 적게 쓸 경우" 등 3종 문구(§6.3 규칙7 · 계산 명세 §5장)
- [ ] **탭마다 결론이 다를 수 있음**을 표현 — 픽스처 P3는 "많이" 탭에서 유지로 뒤집힌다. 오류로 보이지 않게 해야 한다
- [ ] 배분안 표현 — 카드별 역할·금액, 합계 일치가 눈으로 확인되는 배치
- [ ] 단계적 전환 제안 표현(REQ-FUNC-011) — 효과 큰 항목부터. **제시일 뿐 실행 지원이 아님**이 드러나게
- [ ] 계측 포인트 표기 — `result_viewed` · `scenario_tab_opened` · `plan_selected`

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 유지 결론이 정상 결과로 읽힌다**
- Given: `KEEP_CURRENT` 결론 화면 시안이 주어지고
- When: 사용자 테스트에서 "이 화면이 오류인가"를 물으면
- Then: 오류로 인식하지 않는다. 실패색·경고 아이콘·재시도 버튼이 화면에 없다(ADR-01).

**Scenario 2: 기본 탭이 항상 예상대로다**
- Given: 결과 화면이 열린 직후 상태에서
- When: 활성 탭을 확인하면
- Then: 언제나 "예상대로"다. 다른 탭이 기본으로 열리는 시안은 §6.3 규칙6 위반이다.

**Scenario 3 (실패 흐름): 캡션 없는 탭이 없다**
- Given: 탭 3종 시안이 주어지고
- When: 각 탭의 지출 가정 캡션을 세면
- Then: 3개 모두 존재한다. 누락 0건이 판정 기준이다(AC-06).

**Scenario 4 (실패 흐름): 탭 전환이 재계산처럼 보이지 않는다**
- Given: 사전 계산된 3건이 이미 내려온 상태에서
- When: 탭을 전환하면
- Then: 로딩 상태나 재계산 표현이 나타나지 않는다. ADR-03의 "탭 전환 시 재계산 없음"이 화면에서도 지켜진다.
