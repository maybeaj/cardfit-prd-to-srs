## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 같은 400이 서로 다른 코드로 갈라진다**
- Given: 미래지출 0건 요청과 동의 만료 요청이 각각 주어지고
- When: 두 요청을 처리하면
- Then: 둘 다 `400` 이지만 `CF-4001` 과 `CF-4002` 로 구분되고 `requirement` 가 각각 `REQ-EXC-001` · `REQ-EXC-004` 다.

**Scenario 2: 마이데이터 장애는 오류가 아니라 경고다**
- Given: 최근 확인 스냅샷으로 계산이 완료된 상태에서
- When: 응답을 조립하면
- Then: `CF-2001` 이 `warning` 에 실리고 `data` 와 **함께** 반환된다. HTTP 상태는 `200` 이다(REQ-EXC-003).

**Scenario 3 (실패 흐름): 오조회 응답에 타인 정보가 실리지 않는다**
- Given: 응답 주체와 로그인 사용자가 다른 요청이 주어지고
- When: `CF-4030` 응답을 생성하면
- Then: 본문에 코드·메시지 외 어떤 필드도 포함되지 않는다. 조회 대상의 ID·금액·카드명이 하나라도 있으면 **테스트 실패**다(GR5).

**Scenario 4 (실패 흐름): 정의되지 않은 코드는 만들 수 없다**
- Given: 7건 enum이 정의된 상태에서
- When: 매핑 테이블에 없는 코드로 에러 응답을 만들려 하면
- Then: 타입 검사에서 거부된다. 코드가 임의로 늘어나면 클라이언트 분기가 조용히 깨진다.

## ⚙️ Technical & Non-Functional Constraints
- 성능: 코드 매핑은 상수 조회여야 한다. 예외 경로가 `POST /calculate` p95 ≤ 5s를 잠식하지 않게 한다
- 안정성: 모든 실패를 코드가 있는 `error` 봉투로 표현한다. 미분류 5xx는 REQ-NF-003 가용률에 직접 반영된다
- 보안: **`CF-4030`은 GR5 통로다.** 이 코드가 발생하면 컴플라이언스 즉시 통보 대상이며(BE-18), 응답 본문은 최소화한다
- 규제: 사용자 노출 문구는 **금지어 게이트 ②**(C-TEC-007a)의 스캔 대상이다. "대신 해지해 드립니다" 류 표현이 들어가면 배포가 차단된다
