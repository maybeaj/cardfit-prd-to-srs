## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 정상 계산이 3건을 만든다**
- Given: 동의가 유효하고 미래지출이 있는 사용자가 주어지고
- When: 계산을 실행하면
- Then: `SUCCESS` 와 시나리오 3건이 저장되고 마이데이터 호출은 1회다(SD-01).

**Scenario 2 (실패 흐름): 한 시나리오만 실패해도 전체가 중단된다**
- Given: `MORE` 시나리오만 실패하도록 주입한 상태에서
- When: 계산을 실행하면
- Then: 상태가 `PARTIAL` 이고 성공한 2건도 노출되지 않는다. 부분 결과 노출 0건(REQ-EXC-005).

**Scenario 3 (실패 흐름): 미래 입력 0건이면 계산에 들어가지 않는다**
- Given: 미래지출이 0건인 사용자가 주어지고
- When: 계산을 요청하면
- Then: `CF-4001` 이 반환되고 `calculation_input_plans` 에 행이 생기지 않는다(TC-EXC-001).

**Scenario 4 (실패 흐름): 동의 실효 상태로 계산되지 않는다**
- Given: 동의가 만료된 사용자가 주어지고
- When: 계산을 요청하면
- Then: `CF-4002` 가 반환되고 수집·계산이 수행되지 않는다(REQ-EXC-004).

## ⚙️ Technical & Non-Functional Constraints
- 비용: **REQ-NF-005** `collectOnce` 는 반복문 밖. 안으로 들어가면 호출이 3배가 된다(SDD §5.1)
- 성능: **REQ-NF-001** p95 ≤ 5s · 서버리스 하드 타임아웃 0건. 상한 초과 시 ⓐ 분할 저장 ⓑ 백그라운드+폴링 중 선택하되 **탭 전환 재계산 없음은 유지**한다(§1.5.2 갈래③)
- 감사: **REQ-NF-006** 전건 적재. 실패한 계산도 증적을 남긴다
- 상태: **§6.5** `PARTIAL` 은 결과가 아니다
