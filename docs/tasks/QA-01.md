## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 정상 빌드는 게이트를 통과한다**
- Given: 경계값 260건을 만족하고 금지어가 없는 빌드가 주어지고
- When: 배포를 시도하면
- Then: 두 게이트를 통과해 배포된다.

**Scenario 2 (실패 흐름): 계산 오류가 배포를 막는다**
- Given: 경계값 케이스 일부가 실패하는 빌드가 주어지고
- When: 배포를 시도하면
- Then: 게이트 ①이 실패하고 배포가 차단된다(GR1).

**Scenario 3 (실패 흐름): 금지어가 배포를 막는다**
- Given: 실행 대행으로 오인될 문구가 포함된 빌드가 주어지고
- When: 배포를 시도하면
- Then: 게이트 ②가 실패하고 배포가 차단된다(GR4).

**Scenario 4 (실패 흐름): 모델 교체가 스캔을 건너뛰지 않는다**
- Given: 코드 변경 없이 모델 식별자만 바뀐 배포가 주어지고
- When: 배포를 시도하면
- Then: 게이트 ②가 실행된다. 실행되지 않으면 스캔 없이 배포되는 경로가 남는다.

## ⚙️ Technical & Non-Functional Constraints
- 품질: **GR1** 계산 오류율 ≤ 0.1% · **GR4** 금지어 적발 0건
- 기술 제약: **C-TEC-007a** 게이트는 1개만 허용된다. 검증을 위해 단계를 늘리지 않는다
- 검증 방식: **차단을 확인한다.** 통과만 보는 검증은 게이트의 존재를 증명하지 못한다
- 데이터: 경계값 260건은 `params_bound: true` 상태다(GTD §1.4)
