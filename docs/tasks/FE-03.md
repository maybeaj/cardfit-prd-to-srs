## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 유지 결론이 정상 결과로 표시된다**
- Given: `gatingResult: KEEP_CURRENT` 응답(픽스처 P2)이 주어지고
- When: 결과 화면을 렌더링하면
- Then: "현재 조합 유지" 결론이 오류 표현 없이 표시되고, 왜 기준에 못 미치는지가 문장으로 함께 보인다.

**Scenario 2: 탭을 전환해도 요청이 나가지 않는다**
- Given: 시나리오 3건이 담긴 응답을 받은 상태에서
- When: "적게"·"많이" 탭을 차례로 열면
- Then: 네트워크 요청이 0건이고 각 탭에 가정 캡션이 표시된다(ADR-03 · AC-06).

**Scenario 3 (실패 흐름): 캡션이 없는 탭이 있으면 실패다**
- Given: 렌더링된 탭 3종이 주어지고
- When: 캡션 존재 여부를 검사하면
- Then: 3개 모두 존재한다. 하나라도 없으면 테스트 실패다.

**Scenario 4 (실패 흐름): 배분 합계가 어긋나면 표시하지 않는다**
- Given: 배분 합계와 입력 총액의 차이가 1원을 넘는 응답이 주어지고
- When: 배분안을 렌더링하려 하면
- Then: 오류로 처리하고 잘못된 금액을 보여주지 않는다(REQ-FUNC-005).

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-001** `POST /calculate` p95 ≤ 5s · 결론 도달 p95 ≤ 5분. 탭 전환은 즉시 반응해야 한다
- 정확성: 금액은 서버가 준 정수를 그대로 표시한다. **화면에서 반올림·재계산하지 않는다**(REQ-NF-002)
- 규제: "해지" 항목이 포함된 결론에는 경계 안내가 반드시 함께 노출된다(`FE-05` 연계 · AC-03)
- 지표: **ADR-05** — 유지 결론 화면에는 조합안 선택 버튼이 없다. 이 사용자는 북극성 분모에서 제외된다
