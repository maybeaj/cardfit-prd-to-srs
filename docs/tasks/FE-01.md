## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 수정 없이 온보딩을 끝낸다**
- Given: 초기값이 제안된 온보딩 화면이 주어지고
- When: 사용자가 아무것도 고치지 않고 진행하면
- Then: 온보딩이 완료되고 `onboarding_done` 이 적재된다. 직접 입력 강제 필드는 0개다(REQ-FUNC-007).

**Scenario 2: 초기값 수정 여부가 기록된다**
- Given: 제안된 초기값이 표시된 상태에서
- When: 사용자가 한 항목을 수정하고 진행하면
- Then: 해당 항목에 `was_edited` 가 기록된다. 수정률을 관측할 수 없으면 트레이드오프 T3를 확인할 수 없다.

**Scenario 3 (실패 흐름): 동의 없이 진행되지 않는다**
- Given: 동의하지 않은 상태에서
- When: 다음 단계로 이동을 시도하면
- Then: 진행이 막힌다. 동의 범위 밖 수집은 REQ-NF-004 위반이다.

**Scenario 4 (실패 흐름): 동의 만료면 재동의로 보낸다**
- Given: 동의 상태가 만료인 사용자가 주어지고
- When: 계산을 요청하면
- Then: `CF-4002` 를 받아 재동의 유도 화면을 표시한다. 만료 상태로 결과 화면에 도달하지 않는다(REQ-EXC-004).
