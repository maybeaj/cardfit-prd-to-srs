## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1 (실패 흐름): AI가 계산 클래스를 부르면 린트가 막는다**
- Given: `src/domain/ai/ExplanationModule.ts` 가 주어지고
- When: `src/domain/calc/RuleEngine.ts` 를 import 하는 코드를 추가하면
- Then: 린트가 실패하고 빌드가 통과하지 않는다. **이 시나리오가 이 태스크의 존재 이유다**(ADR-02).

**Scenario 2: 결과를 인자로 받는 것은 허용된다**
- Given: `ExplanationModule` 이 계산 결과 DTO를 인자로 받는 시그니처를 가지고
- When: 계약 모듈(`src/contracts/`)만 import 하면
- Then: 린트를 통과한다. 금지되는 것은 **호출**이지 결과 사용이 아니다.

**Scenario 3 (실패 흐름): 데이터 계층이 응용 계층을 부르면 막는다**
- Given: 데이터 계층 모듈이 주어지고
- When: 응용 계층 서비스를 import 하면
- Then: 린트가 실패한다(SDD §2.4 규칙 1).

**Scenario 4 (실패 흐름): 마이데이터 어댑터를 우회 호출하면 막는다**
- Given: `MyDataConnector` 외의 모듈이 주어지고
- When: 마이데이터 어댑터를 직접 import 하면
- Then: 린트가 실패한다. 호출을 한 곳에서 세지 못하면 결론 1건당 ≤ 1회(REQ-NF-005)를 보증할 수 없다.

## ⚙️ Technical & Non-Functional Constraints
- 성능: 린트 실행이 개발 루프를 늦추지 않게 캐시를 사용한다
- 안정성: **규칙을 끄는 인라인 주석(`eslint-disable`)을 경계 규칙에 대해서는 금지**한다. 예외를 허용하면 경계가 사실상 사라진다
- 아키텍처: 단일 코드베이스라 배포 경계로 강제할 수 없다. **ADR-02를 지키는 책임이 아키텍처에서 규칙 검사로 옮겨왔다**(§1.5.1 신규 제약 ①)
- 순서: **코드가 쌓이기 전에 세워야 한다.** 나중에 넣으면 이미 넘어간 의존성을 되돌리는 작업이 함께 붙는다
